## 批量与重试参数

- `get_history_instruments` 日常同步采用 20--25 个代码一批；50 个代码虽然成功，但返回 79,450 行、耗时约 9.95 秒，不作为稳定生产批量。
- 200 个代码一次请求会因结果集过大失败，不得使用。
- 每批完成后立即提交本地事务；失败批次拆半重试，最小拆到单代码。
- 网络或服务端暂时错误采用 1、2、4 秒指数退避，最多 3 次；权限错误、参数错误、结果集过大不做原样重试。
- 分钟线按单个首板事件窗口请求，不与长期历史证券状态使用相同批量。

## 采用的数据契约

1. 长期日线 OHLCV/成交额/`pre_close`：优先使用 `gm.api.history(..., frequency='1d', adjust=0)`。
2. 每个交易日的涨跌停价与证券状态：使用 `gm.api.get_history_instruments`，以 `(symbol, trade_date)` 关联；`upper_limit` 和 `lower_limit` 是权威值。
3. 仅在权威涨跌停价缺失时，才按 `pre_close`、板块规则和价格最小变动单位计算候选值；两者不一致必须标记异常，不能静默覆盖。
4. 分钟数据仅按首板事件窗口缓存，且只请求服务端许可的近 180 日范围；不得下载全市场半年分钟线。
5. 停牌、退市或无近期分钟线必须以 `no_data` 独立记录；它不是网络故障，也不能生成交易信号。

## 对本地数据的影响

当前 SQLite 的 `a_share_daily_bars` 只覆盖 2026-05-06 至 2026-07-21，且没有 `pre_close`、`upper_limit`、`lower_limit`。它不能直接用于 2020 年起的回测，必须在 PR6.1/PR6.2 依据本契约补齐缺失日线和证券日状态。

当前行业成分是 2026-07-22 的当前快照，历史使用会产生未来函数风险。PR6.1 必须将该限制显式标注；在取得历史成分快照前，行业过滤只能作为近似研究维度，不能宣称严格历史回测。

## 边界规则的后续验收

- 主板样本已验证约 10% 涨跌停价，创业板/科创板样本已验证约 20%，停牌/ST 特殊样本已返回约 5% 的权威涨跌停价及 `is_suspended`。
- 除权除息、新股无涨跌停限制日仍必须作为 PR6.1 数据契约的固定测试样本；在明确权威字段含义前，这些日期默认标记 `quality_flags` 并排除策略信号。

PR6.0 的数据能力与请求边界已审计完成，可以进入 PR6.1。严格长期策略回测仍须等待 PR6.1/PR6.2 补齐本地数据，并解决历史行业成分快照的未来函数风险。
